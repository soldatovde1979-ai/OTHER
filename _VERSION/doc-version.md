# Версионирование сборки — инструкция пользователя

## Зачем

Чтобы на вопрос «что сейчас установлено и из чего собрано» был ответ,
который видно, а не вычисляют сравнением файлов. Версия живёт внутри
артефакта (в настройках, в подвале отчёта, в файле версии) и в журнале
версий. Имя файла артефакта не меняется — ярлыки и скрипты остаются рабочими.

## Одна команда

Из корня проекта, артефакт должен быть закрыт:

```
powershell -NoProfile -ExecutionPolicy Bypass -File install\install.ps1
```

Что происходит по шагам:

1. считаются хеши исходников и сравниваются с прошлым релизом;
2. выполняется сборка/установка артефакта;
3. **только если сборка вернула код 0**: поднимается версия, она записывается
   в артефакт, прогоняются недостающие миграции, добавляется запись в
   CHANGELOG.md.

Если сборка упала — версия не меняется, журнал не трогается. Это и есть
правило «версия фиксируется только при нулевом коде возврата».

Посмотреть, что будет сделано, ничего не трогая:

```
powershell -NoProfile -ExecutionPolicy Bypass -File install\install.ps1 -DryRun
```

## Первый запуск

Механизм заводится с нуля, поэтому первый прогон ведёт себя не так, как
обычный: прошлого состояния ещё нет, в выводе будет `RELEASE_FIRST_RUN`,
**версия не поднимается** — фиксируется текущая версия как точка отсчёта.

Порядок действий:

1. Закрыть артефакт.
2. Предпросмотр: `... install.ps1 -DryRun`.
3. Если вывод разумный — тот же запуск без `-DryRun`. Успех выглядит как
   `RELEASE_OK <версия>`.
4. Открыть артефакт и проверить, что версия в нём появилась.

Если сборка упадёт — версия и журнал останутся нетронутыми, артефакт можно
вернуть из резервной копии (инсталлер делает её до любых правок).

## Какой номер получится

Номер — `МАЖОР.МИНОР.ПАТЧ`. Выбор — по правилу «кто заметит разницу и надо ли
ему что-то делать»:

| Что произошло | Команда | Результат |
|---|---|---|
| Правка внутри, поведение то же, никто не заметит | обычный запуск | патч: 8.1.0 → 8.1.1 |
| Новая возможность: заметно, но делать ничего не нужно | `-Bump minor` | 8.1.1 → 8.2.0 |
| Сменился контракт: придётся вмешаться руками, иначе сломается | `-Bump major` | 8.2.0 → 9.0.0 |
| Исходники не менялись, просто переустановка | обычный запуск | версия та же |

```
powershell -NoProfile -ExecutionPolicy Bypass -File install\install.ps1 -Bump minor
```

Патч считается сам. Минор и мажор — осознанное решение, поэтому их задают
флагом.

## Где смотреть версию

| Где | Что видно |
|---|---|
| Артефакт (настройки, подвал отчёта, файл версии) | `BUILD/VERSION`, `BUILD/DATE`, `BUILD/SRC_MD5` |
| `install\VERSION` | версия исходников (первая строка) и описание |
| `CHANGELOG.md` | что менялось от версии к версии |

`BUILD/SRC_MD5` отвечает на вопрос «артефакт совпадает с исходниками или
разошёлся»: если после правки исходников хеш в артефакте прежний — правку в
него никто не ставил.

## Файлы механизма

| Файл | Назначение | Правится руками |
|---|---|---|
| `install\VERSION` | первая строка — версия, дальше описание | нет, ведёт install.ps1 |
| `install\release.state` | хеши исходников прошлого релиза | **никогда** |
| `CHANGELOG.md` | накопительный журнал версий | нет, ведёт install.ps1 |
| `install\migrations\*.ps1` | дополнительный код версии | да, при необходимости |
| `install\install.ps1` | сам механизм | редко |

## Если что-то пошло не так

| Маркер в выводе | Что значит |
|---|---|
| `RELEASE_SOURCES_SAME` | исходники не менялись, версия не поднимается — это нормально |
| `RELEASE_FAIL` | релиз прерван; версия, журнал и состояние не тронуты |
| `ARTIFACT_ERROR` | сборка прошла, но версию в артефакт записать не удалось |
| `MIG_SKIP` | миграция старше версии артефакта, применять нечего |
| `RELEASE_OK <версия>` | всё прошло, в артефакте записана новая версия |

## Чего механизм не делает

- **не переименовывает артефакт** — сознательно: имя файла как носитель версии
  ломает ярлыки и списки недавних документов, а на синхронизируемой папке
  каждое переименование — повторная заливка всего файла;
- **не пишет версию, если сборка не прошла** — при любом ненулевом коде
  сборки `VERSION`, `release.state` и `CHANGELOG.md` остаются прежними;
- **не трогает данные** — данные, настройки и подключения инсталлер не
  меняет, миграции работают только с тем, что явно описано в них.
