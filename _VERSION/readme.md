# _VERSION — подсистема версионирования сборки

## Зачем нужна

Даёт ответ на вопросы «какая версия сейчас установлена» и «из чего она собрана» — так, чтобы
ответ был виден в артефакте, а не вычислялся сравнением файлов. Механизм универсален
(Excel-книга, конфигурация 1С, веб-сайт, исполняемый файл): всё, что зависит от типа артефакта,
сводится к заполнению точек адаптации в скрипте. Правило: версия фиксируется только при
нулевом коде возврата сборки.

## Описание файлов

| Файл | Назначение |
|---|---|
| [`doc-version.md`](doc-version.md) | инструкция пользователя: одна команда установки, первый запуск, выбор номера версии, где смотреть версию, файлы механизма, маркеры ошибок |
| [`spec-version-add.md`](spec-version-add.md) | инструкция агента: как внедрить механизм версионирования в произвольный проект |
| [`spec-version-work.md`](spec-version-work.md) | инструкция агента: работа с уже внедрённым механизмом (правило нулевого кода, патч/минор/мажор) |
| [`install.ps1`](install.ps1) | шаблон универсального механизма install + release: хеши исходников, сборка/установка артефакта, подъём версии, миграции, запись в CHANGELOG; содержит точки адаптации |
| [`install_prod.ps1`](install_prod.ps1) | тонкая надстройка: запускает [`install.ps1`](install.ps1) с прод-целью и возвращает его код |

Скрипты — шаблоны с точками адаптации; переносятся в проект папкой `install\` и обязаны
оставаться в кодировке UTF-8 с BOM.
