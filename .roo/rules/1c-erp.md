# 1c-erp
# Правила работы с проектом 1C_ERP (конфигурация 1С)

## Обязательный контекст

Перед началом работы с задачей прочитать:
- [`README.md`](../../README.md) — идентификация конфигурации и состав решения;
- [`docs/metadata-map.md`](../../docs/metadata-map.md) — формат выгрузки, каталоги, правила навигации;
- [`docs/prefix-glossary.md`](../../docs/prefix-glossary.md) — расшифровка префиксов доработок.

Ключевые факты: конфигурация **«УправлениеХолдингомERP»** («1С:ERP. Управление холдингом», Версия 110), выгрузка в файлы формата Конфигуратора (Hierarchical 2.20). Корень репозитория = корень конфигурации.

## Идентификация объектов

1. **Префиксы доработок**: `шх` (шинное хозяйство), `уат` (автотранспорт), `т1к` (Т1), `eam` (ТОиР), `Itob` (спутниковый мониторинг). Эти объекты — основная зона кастомизации.
2. **Типовые объекты** (без префикса, включая `ЗарплатаКадры*`, `*УХ`, `БСП`) — не модифицировать без явного указания пользователя. При необходимости правки типового модуля предложить вынос логики в объект с префиксом или подписку на событие.
3. Перед правкой логики записи/проведения проверять [`EventSubscriptions/`](../../EventSubscriptions/) — часть логики может быть вынесена в подписки.

## Навигация по выгрузке

- Описание объекта: `<Тип>/<Имя>.xml`; модуль объекта: `<Тип>/<Имя>/Ext/ObjectModule.bsl`; модуль набора записей: `Ext/RecordSetModule.bsl`; модуль менеджера: `Ext/ManagerModule.bsl`; модуль формы: `Forms/<Форма>/Ext/Form/Module.bsl`; общий модуль: `CommonModules/<Имя>/Ext/Module.bsl`.
- Имя файла = имя объекта метаданных. Для поиска объекта использовать поиск по имени файла в каталоге соответствующего типа, затем точечное чтение.
- `ConfigDumpInfo.xml` (~236 тыс. строк) и `Configuration.xml` (~26 тыс. строк) — служебные; читать их выборочно (поиском по подстроке), не целиком.

## Правила правок BSL

1. Стиль — встроенный язык 1С, русские идентификаторы, области `#Область` в начале модуля, комментарии на русском.
2. Сохранять структуру областей и порядок процедур; новые процедуры помещать в подходящую область, не в конец модуля.
3. Учитывать директивы препроцессора (`#Если Сервер Или ... Тогда`) — не ломать условную компиляцию.
4. При работе с запросами использовать параметры `&Параметр` и временные таблицы в стиле существующего кода; не использовать подстановку значений в текст запроса.
5. Не менять сигнатуры экспортных процедур/функций типовых и отраслевых модулей без запроса — иначе сломаются вызовы из других модулей.
6. После правки BSL проверять синтаксис (BSL Language Server / SonarLint), баланс `Если...КонецЕсли`, `Процедура...КонецПроцедуры`.

## Ограничения среды

- Выгрузка в файлы не исполняется: правки не влияют на информационную базу до загрузки в Конфигураторе («Конфигурация → Загрузить конфигурацию из файлов»).
- Конфигурация на поддержке: если объект не снят с поддержки, загрузка изменений будет отклонена — предупреждать об этом при правках типовых объектов.
- Нет доступа к самой ИБ: для тестирования логики пользователь загружает файлы и запускает проверки в 1С.

## Рабочий процесс

1. Локализовать объект по карте метаданных.
2. Прочитать целевые модули и связанные вызовы (поиск по `CommonModules`).
3. Внести минимально необходимые правки, не трогая несвязанный код.
4. Перечислить пользователю изменённые файлы и шаги проверки в 1С.
