# spec-version-contract — контракт ядра и адаптеров

Обязательный документ для авторов адаптеров и для всех, кто правит ядро.
Разделение: ядро знает «когда и в каком порядке», адаптер знает «как именно
для этого артефакта». Ядро НЕ знает, что собирается: Excel, 1С, веб, exe.

## Зона ответственности ядра (`install.ps1`)

1. дайджест исходников (`release.state`, хеши каждого файла);
2. сравнение с прошлым релизом, подъём версии (патч/минор/мажор);
3. защита от отката: штамп артефакта против версии исходников;
4. вызов адаптера: сборка, затем проверка (обе с кодом возврата 0);
5. версия и счётчик релизов при успехе: `VERSION`, `release.state`, штамп;
6. миграции по версии, записанной в артефакте;
7. `CHANGELOG.md`: человеческое описание из `install\VERSION`, затем техника;
8. `install\build-info.json`: манифест релиза.

## Зона ответственности адаптера (`adapters\<тип>\`)

Адаптер — набор `.ps1`-файлов с фиксированными именами и сигнатурами. Ядро
вызывает их в строго заданные моменты. Адаптер обязан завершаться с кодом 0
при успехе и ненулевым при сбое; свободный текст — в маркерном виде.

### Файлы адаптера и сигнатуры

| Файл | Функция | Сигнатура и поведение |
|---|---|---|
| `build.ps1` | сборка/установка артефакта | `param([string]$Target)`. Успех → код 0; сбой → ненулевой. Исходники читает сам (передаётся `$env`-ом или параметром `-SourceRoot`) |
| `verify.ps1` | пост-проверка (компиляция и т.п.) | `param([string]$Target)`. Успех → код 0. Для Excel — компиляция VBA на временной копии |
| `stamp.ps1` | чтение/запись штампа версии | режим `Read`: `param([string]$Target, [switch]$Read)` → печатает `STAMP_VERSION`, `STAMP_DATE`, `STAMP_MD5`, `STAMP_RELEASE_NO` (отсутствие = `0.0.0`/пусто); режим записи: параметры `-Version -Date -Md5 -ReleaseNo` |
| `context.ps1` | выполнение миграции в процессе адаптера | `param([string]$Target, [string]$Migration)`: открыть артефакт, выполнить `-Migration` с параметрами `-Workbook -BookPath`, сохранить и закрыть |

Единое требование к выводу: каждая строка — `МАРКЕР детали`, кириллица — UTF-8.
Ядро читает только код возврата и строки `STAMP_*`. Миграции выполняются
адаптером: `context.ps1` открывает артефакт, вызывает скрипт миграции
(`-Workbook` / `-BookPath`), сохраняет и закрывает.

### Маркеры адаптера (допустимые)

| Маркер | Смысл |
|---|---|
| `BUILD_OK` / `BUILD_FAIL` | итог сборки (дублирует код возврата) |
| `VERIFY_OK` / `VERIFY_FAIL` | итог проверки |
| `STAMP_VERSION` / `STAMP_DATE` / `STAMP_MD5` / `STAMP_RELEASE_NO` | штамп прочитан |
| `STAMP_WRITTEN` | штамп записан |
| `CONTEXT_OPEN` / `CONTEXT_SAVED` / `MIG` | контекст миграции открыт / изменения сохранены / вывод миграции |

## Правило «где живёт версия» (ядро проверяет при внедрении)

1. **Скрипты-утилиты** (`*.ps1`, автономные инструменты) — версия в шапке файла:
   `# Version X.Y / ГГГГ-ММ-ДД: что изменилось`.
2. **Рабочий артефакт** — штамп внутри него. Excel: `CustomDocumentProperties`
   (`BuildVersion`, `BuildDate`, `BuildSrcMd5`, `BuildReleaseNo`); exe — ресурс
   сборки; веб — `version.json` в дистрибутиве; 1С — константа.
3. **Имя файла** несёт версию ТОЛЬКО у неизменяемых снимков/архивов
   (`app-1.2.3.msi`, `Отчёт-2026-09-16-v8.xlsx` — то, что публикуют и не правят).
4. **Fallback** для артефактов без внутреннего поля — `version.json` **рядом**
   с артефактом, никогда не в имени рабочего файла.

Запрещено: версия в имени рабочего файла, на который ссылаются ярлыки, скрипты
и синхронизация (переименование ломает ссылки и вызывает повторную заливку).

## Слои версии (едины для всех проектов)

- **SemVer** `МАЖОР.МИНОР.ПАТЧ` — человеческий смысл изменений.
- **Счётчик релизов** — монотонный номер успешного релиза, +1 за релиз,
  хранится в `release.state` (ключ `release_no`), виден как `8.1.9 (10)`.
- **Манифест** `install\build-info.json` — `release_no`, `version`, `date`,
  `digest`, `files[{path, md5}]`. Генерируется ядром, руками не правится.

## Требования к новому адаптеру

1. Та же пятёрка файлов с теми же сигнатурами.
2. Все сбои — ненулевым кодом возврата, текст — маркерами.
3. Штамп пишется только в момент `STAMP_WRITTEN`, после успешной сборки и
   проверки (правило «версия только при нулевом коде»).
4. `spec-<тип>.md` рядом с адаптером: что является продом/сборкой, где штамп,
   ограничения артефакта (для Excel: книга закрыта, UTF-8 BOM, COM-инстанс).
5. Идемпотентность сборки: повторный прогон без изменений не должен ломать
   артефакт.
