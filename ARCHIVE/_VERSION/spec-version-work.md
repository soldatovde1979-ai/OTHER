# spec-version-work — работа с версией сборки

Инструкция для агента по работе с уже внедрённым механизмом версионирования.
Самодостаточна: все правила и таблицы маркеров — в этом файле, никуда ходить
не нужно. Применима к любому проекту (Excel, 1С, веб, исполняемые файлы).

## Устройство механизма

- `install\install.ps1` — объединение install + release: считает хеши
  исходников, сравнивает с прошлым релизом, устанавливает/собирает артефакт и
  ТОЛЬКО при нулевом коде сборки поднимает версию, записывает её в артефакт,
  прогоняет недостающие миграции и добавляет запись в CHANGELOG.md.
- `install\install_prod.ps1` — надстройка «install с ключами продуктива»:
  запускает install.ps1 с прод-целью и возвращает его код.
- `install\VERSION` — первая строка: версия (SemVer), ниже — человеческое
  описание изменений, заполняется руками ДО релиза.
- `install\release.state` — хеши исходников прошлого успешного релиза.
- `install\migrations\` — дополнительный код версий.
- `CHANGELOG.md` — журнал версий: сначала человеческое описание из
  `install\VERSION`, затем техническая часть; новая запись сверху.

## Главное правило

Версия фиксируется ТОЛЬКО при нулевом коде возврата сборки. Сборка упала —
версия, `release.state` и `CHANGELOG.md` остаются прежними, артефакт можно
откатить из резервной копии (её делает инсталлер до любых правок). Никогда
не поднимай версию и не правь журнал руками, обходя это правило.

## Выбор номера: патч, минор или мажор

Номер — `МАЖОР.МИНОР.ПАТЧ`. Критерий выбора — «кто заметит разницу и надо ли
ему что-то делать»:

| Кто заметит | Уровень | Команда |
|---|---|---|
| Никто не заметит (правка внутри кода, поведение то же) | патч (автомат) | обычный запуск |
| Заметит, но делать ничего не нужно (новая возможность) | минор | `-Bump minor` |
| Заметит и придётся вмешаться руками, иначе сломается (сменился контракт: схема данных, параметры, форматы) | мажор | `-Bump major` |

Мажор — это также любое изменение определения метрики/показателя, после
которого новые числа несопоставимы со старыми. Патч считается сам; минор и
мажор — осознанное решение человека, поэтому задаются флагом.

## Порядок релиза

1. Закрыть артефакт (книгу, базу, приложение), если он открыт.
2. Вписать в `install\VERSION` ниже первой строки человеческое описание
   изменений: **что** добавлено; **какая** ошибка исправлена (какая, а не как
   исправлялась); **что** и с **каким результатом** оптимизировано. Описание
   попадёт в `CHANGELOG.md` первым абзацем записи новой версии.
3. Предпросмотр, ничего не меняя:

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File install\install.ps1 -DryRun
   ```

4. Прочитать вывод. Ожидаемые маркеры:
   - `RELEASE_SOURCES_SAME` — исходники не менялись, версия не поднимется;
   - `RELEASE_SOURCES_CHANGED` + `RELEASE_VERSION_NEXT` — что изменилось и
     какая версия получится;
   - `RELEASE_FIRST_RUN` — прошлого состояния нет, версия не поднимается,
     фиксируется текущая как точка отсчёта;
   - `DESC_FOUND <кол-во строк>` / `DESC_EMPTY` — есть ли описание для
     CHANGELOG; при `DESC_EMPTY` вернуться к шагу 2.
5. Если вывод разумный — запуск без `-DryRun` (при необходимости с
   `-Bump minor|major`).
6. Успех выглядит как `RELEASE_OK <версия>` и код возврата 0.

Идемпотентность: повторный прогон при неизменных исходниках версию не
накручивает и дублей в CHANGELOG не создаёт.

## Миграции

Миграция нужна, когда новой версии мало установить код — надо доделать сам
артефакт: завести ключ настройки, перестроить таблицу, почистить данные.

Правила:

- имя файла: `install\migrations\<версия>__<короткое_имя>.ps1`;
- применяется, если её версия БОЛЬШЕ версии, записанной в артефакте;
- порядок — по возрастанию версии;
- строка `# requires-from: <версия>` в первых 20 строках означает «артефакт
  ниже этой версии миграцией не обновлять»: релиз остановится и скажет, какую
  промежуточную версию поставить сначала;
- сигнатура: `param($Target, $Context)` — путь к артефакту и контекст,
  открытый точкой адаптации; миграция НЕ сохраняет и не закрывает артефакт;
- миграция обязана быть идемпотентной: повторный прогон не должен ломать
  данные;
- вывод миграции попадает в релиз с префиксом `MIG`.

Заготовка:

```powershell
# <версия>__описание.ps1
# requires-from: <версия>
param($Target, $Context)
$ErrorActionPreference = "Stop"

# ... работа с артефактом через $Target/$Context ...
Write-Output "что сделано"
```

## Запреты

- Не править руками `install\release.state` и `CHANGELOG.md` — их ведёт
  install.ps1.
- В `install\VERSION` руками правится ТОЛЬКО описание ниже первой строки.
  Первую строку (версию) ведёт install.ps1.
- Не переносить версию в имя файла артефакта: ломаются ярлыки и пути.
- Не прогонять релиз с открытым артефактом.
- Не поднимать версию при ненулевом коде сборки.
- Не менять миграции задним числом после релиза: применяется только то, что
  ещё не применялось.

## Маркеры вывода и действия

| Маркер | Значение | Действие |
|---|---|---|
| `TARGET` | цель установки, полный путь | убедиться, что это нужный артефакт |
| `RELEASE_FIRST_RUN` | прошлого состояния нет, версия не поднимается | штатно для первого прогона |
| `RELEASE_SOURCES_SAME` | исходники не менялись, версия прежняя | штатно |
| `RELEASE_SOURCES_CHANGED` | список изменившихся исходников | проверить список перед запуском |
| `RELEASE_VERSION_NEXT` | версия после подъёма | проверить уровень (патч/минор/мажор) |
| `DESC_FOUND` | описание для CHANGELOG прочитано из install\VERSION | штатно |
| `DESC_EMPTY` | описание не заполнено | вписать описание в install\VERSION и повторить релиз |
| `RELEASE_DRYRUN` | предпросмотр завершён, ничего не тронуто | штатно |
| `TARGET_NOT_FOUND` | цель сейчас не существует | если сборка создаёт её заново — штатно |
| `STEP` / `BUILD_OK` | этапы и результат сборки | штатно |
| `ARTIFACT_VERSION` | версия в артефакте до прогона | штатно |
| `MIG_RUN` / `MIG_SKIP` | миграция применена / пропущена | штатно |
| `VERSION_WRITTEN` / `STATE_WRITTEN` / `CHANGELOG_WRITTEN` | файлы механизма обновлены | штатно |
| `RELEASE_OK <версия>` | релиз завершён, код возврата 0 | штатно, финал |
| `ARTIFACT_ERROR` | сборка прошла, но версия/миграции в артефакт не записаны | разобрать сообщение, версия не изменена |
| `RELEASE_FAIL` | релиз прерван, код возврата 1 | разобрать сообщение; версия, state и CHANGELOG не тронуты |

Дополнительно у надстройки `install_prod.ps1`: `PROD_TARGET` (прод-цель),
`RUNNING` (запуск install.ps1), `INSTALL_EXIT` (код возврата),
`PROD_OK` / `PROD_FAIL` (итог установки).

## Обычный сценарий правки

Поменял исходники → прогон install.ps1 на build-артефакте (не прод) → прогон
тестов до зелёного → только затем релиз на прод через install.ps1. Прод до
зелёных тестов запрещён: недогруженный код даёт ошибки на живом артефакте.
