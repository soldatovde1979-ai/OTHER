# Карта метаданных конфигурации «УправлениеХолдингомERP»

## 1. Формат выгрузки и структура объекта

Выгрузка выполнена Конфигуратором в формате «Hierarchical» (v2.20). Каждый объект метаданных раскладывается так:

| Артефакт | Путь |
|---|---|
| Описание объекта (реквизиты, ТЧ, команды) | `<Тип>/<Имя>.xml` |
| Модуль объекта (справочники, документы, задачи) | `<Тип>/<Имя>/Ext/ObjectModule.bsl` |
| Модуль менеджера | `<Тип>/<Имя>/Ext/ManagerModule.bsl` |
| Модуль набора записей (регистры) | `<Тип>/<Имя>/Ext/RecordSetModule.bsl` |
| Модуль записи (регистры расчёта, бухгалтерии) | `<Тип>/<Имя>/Ext/WriteModule.bsl` (если есть) |
| Общий модуль | `CommonModules/<Имя>.xml` + `CommonModules/<Имя>/Ext/Module.bsl` |
| Описание формы | `<Тип>/<Имя>/Forms/<Форма>.xml` |
| Элементы формы | `<Тип>/<Имя>/Forms/<Форма>/Ext/Form.xml` |
| Модуль формы | `<Тип>/<Имя>/Forms/<Форма>/Ext/Form/Module.bsl` |
| Макет | `<Тип>/<Имя>/Ext/Template...` или `Forms/<Форма>/Ext/Template...` |

Пример: регистр расчёта «Начисления»:
- [`CalculationRegisters/Начисления.xml`](../CalculationRegisters/Начисления.xml) — описание;
- [`CalculationRegisters/Начисления/Ext/RecordSetModule.bsl`](../CalculationRegisters/Начисления/Ext/RecordSetModule.bsl) — модуль набора записей.

## 3. Ключевые блоки решения

### Ядро ERP (типовое)
- Подсистемы: `Продажи`, `ПродажиБазовая`, `Закупки`, `Склад`, `Производство`, `РегламентированныйУчет`, `БанкИКассаБазовая`.
- Расчёт зарплаты: подсистемы `Зарплата`, `Кадры`, `ЗарплатаКадрыРасширеннаяПодсистемы`; регистры расчёта `Начисления` и `Удержания`.

### Холдинговые блоки (УХ)
- `БюджетированиеИПланирование`, `КазначействоУХ`, `КонсолидацияПоМСФО`, `МеждународныйФинансовыйУчет`, `УправлениеДоговорамиИПроектами`, `УправлениеРисками`.

### EAM (ТОиР), префикс `eam`
- Подсистемы: `eamБазаДанныхОборудования`, `eamПланированиеТОиР`, `eamУправлениеРаботамиТОиР`, `eamУчетДефектов`, `eamРесурсообеспечениеТОиР`.
- Ключевые справочники: `eamЕдиницыОборудования`, `eamТехническиеМеста`, `eamВидыРабот`, `eamДефекты`, `eamМоделиЕО`.
- Регистр накопления: `ЭтапыПроизводства` (обслуживается EAM-блоком).

### ITOB (спутниковый мониторинг), префикс `Itob`
- Справочники: `ItobТерминалы`, `ItobДатчики`, `ItobТранспортныеСредства`, `ItobМаршруты`, `ItobГеографическиеЗоны`, `ItobRFIDКарты`.
- Модули: `ItobПутевыеЛисты`, `ItobОбработкаДанныхТопливо*`, `ItobОперативныйМониторинг*`, `ItobРепликация*`, `ItobЦентрСпутниковогоМониторинга*`.

### Шинное хозяйство (ШХ), префикс `шх`
- Регламентные задания в `ScheduledJobs/шх*.xml` (загрузка из ЭСМО, сервис маслораздачи, медосмотры, портал услуг, сервер ключей, кадровая история).
- Регистр накопления: `шхПересортицаКЗДЗ`, `шхЛимитыПоДоговорам`.

### Автотранспорт (УАТ), префикс `уат`
- Подсистемы: `уатУправлениеАвтотранспортом`, `уатСлужебныеОбъекты`, `уатСлужебнаяОбъектыУСО`.
- Журнал: `DocumentJournals/уатДокументыГСМ`.

### Блок Т1, префикс `т1к`
- Подсистемы: `т1кАдминистрированиеШХ`, `т1кНаземноеОбслуживание`, `т1кПланированиеЗакупок`, `т1кУчетПОЖ_КомандныйИнтерфейс`, `т1кФункциональныеПодсистемы`.

## 4. Как искать объекты

Поиск по имени объекта в выгрузке (имя файла = имя объекта):

```powershell
Get-ChildItem -Recurse -Filter "Начисления*" | Select-Object FullName
```

Ограничить поиск типом — искать внутри каталога типа. Для поиска вхождений по содержимому BSL:

```powershell
Select-String -Path "CommonModules\*.bsl" -Pattern "Функция ЗагрузитьДанныеИзЭСМО"
```

В агентских инструментах предпочтительны: поиск по файлам (`*.xml`, `*.bsl`) в каталоге нужного типа, затем точечное чтение файла.

## 5. Соглашение о «типовом» и «доработанном»

- Объекты без префикса и с префиксами типовых блоков (`ЗарплатаКадры`, `УХ`, `БСП`-служебные) считаются **типовыми** — их модификация требует явного запроса пользователя.
- Объекты с префиксами `шх`, `уат`, `т1к`, `eam`, `Itob` — отраслевые доработки, основная зона работ.
- Перед правкой модуля проверять обработчики подписок `EventSubscriptions/` — часть логики может быть вынесена туда.
