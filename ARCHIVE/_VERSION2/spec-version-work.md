# spec-version-work — работа с внедрённым механизмом

Инструкция для агента и владельца проекта, где механизм уже внедрён.
Самодостаточна: все правила и таблица маркеров — здесь.

## Устройство

- `install\install.ps1` — ядро: хеши исходников, защита от отката, сборка и
  проверка через адаптер, версия и счётчик релизов, миграции, CHANGELOG,
  манифест.
- `install\install_prod.ps1` — прод-обёртка.
- `install\VERSION` — первая строка: SemVer; ниже — человеческое описание
  следующего релиза (заполняется руками ДО релиза).
- `install\release.state` — хеши исходников и `release_no` прошлого релиза.
- `install\build-info.json` — манифест последнего релиза.
- `CHANGELOG.md` — журнал: человеческое описание, затем техника, сверху новая.

## Главное правило

Версия и счётчик фиксируются ТОЛЬКО при нулевом коде сборки и проверки. Сбой —
`VERSION`, `release.state`, `CHANGELOG.md` и `build-info.json` не тронуты.

## Выбор номера: патч, минор или мажор

Критерий — «кто заметит разницу и надо ли ему что-то делать»:

| Кто заметит | Уровень | Команда |
|---|---|---|
| Никто (правка внутри, поведение то же) | патч | обычный запуск |
| Заметит, делать ничего не нужно | минор | `-Bump minor` |
| Заметит и придётся вмешаться, иначе сломается (контракт) | мажор | `-Bump major` |

Патч считается сам; минор/мажор — осознанное решение флагом.

## Порядок релиза

1. Закрыть артефакт, если открыт.
2. Вписать в `install\VERSION` ниже первой строки человеческое описание:
   **что** добавлено; **какая** ошибка исправлена (какая, а не как); **что** и
   с **каким результатом** оптимизировано. Оно попадёт в CHANGELOG первым
   абзацем записи.
3. `-DryRun` — предпросмотр, ничего не меняя.
4. Прочитать вывод: `RELEASE_SOURCES_SAME` / `RELEASE_SOURCES_CHANGED` +
   `RELEASE_VERSION_NEXT` / `RELEASE_FIRST_RUN`; `DESC_FOUND` / `DESC_EMPTY`
   (пусто → вернуться к шагу 2).
5. Боевой запуск (при необходимости `-Bump minor|major`).
6. Успех: `RELEASE_OK <версия> (n)` и код 0; проверить `build-info.json`.

## Миграции

Имя: `install\migrations\<версия>__<имя>.ps1`; применяется, если её версия
больше версии, записанной в артефакте; `# requires-from:` — минимальная
версия артефакта; идемпотентность обязательна. Ядро выбирает миграции, а
выполняет их адаптер (`context.ps1`): открывает артефакт, вызывает миграцию
(`-Workbook` / `-BookPath`), сохраняет и закрывает.

## Запреты

- Не править руками `release.state`, `build-info.json`, `CHANGELOG.md` и
  первую строку `VERSION` (описание ниже первой строки — наоборот, руками).
- Не переносить версию в имя рабочего файла артефакта.
- Не релизить с открытым артефактом.
- Не менять миграции задним числом после релиза.

## Маркеры вывода

| Маркер | Значение | Действие |
|---|---|---|
| `RELEASE_TARGET` | цель установки | убедиться, что это нужный артефакт |
| `RELEASE_FIRST_RUN` | прошлого состояния нет, версия не поднимается | штатно для первого прогона |
| `RELEASE_SOURCES_SAME` | исходники не менялись | штатно |
| `RELEASE_SOURCES_CHANGED` | список изменившихся исходников | проверить список |
| `RELEASE_VERSION_NEXT` | версия после подъёма | проверить уровень |
| `DESC_FOUND` / `DESC_EMPTY` | описание для CHANGELOG есть / нет | при EMPTY — вписать описание |
| `BUILD_OK` / `BUILD_FAIL` | итог сборки адаптера | — |
| `VERIFY_OK` / `VERIFY_FAIL` | итог проверки | — |
| `RELEASE_NO <n>` | счётчик релизов после инкремента | штатно |
| `STAMP_WRITTEN` | штамп записан в артефакт | штатно |
| `MIG_RUN` / `MIG_SKIP` | миграция применена / пропущена | штатно |
| `VERSION_WRITTEN` / `STATE_WRITTEN` | файлы механизма обновлены | штатно |
| `BUILDINFO_WRITTEN` | манифест обновлён | штатно |
| `CHANGELOG_WRITTEN` | запись в журнал добавлена | штатно |
| `RELEASE_OK <версия> (n)` | релиз завершён, код 0 | финал |
| `RELEASE_FAIL` | релиз прерван, код 1 | разобрать сообщение; версия, журнал, state и манифест не тронуты |
