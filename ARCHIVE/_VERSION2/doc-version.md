# doc-version — версионирование сборки: обзор для человека

Зачем: чтобы на вопрос «что сейчас стоит в продуктиве» был ответ, который
видно, а не вычисляют сравнением файлов. Механизм — [`install.ps1`](install.ps1)
(ядро) + адаптер сборки конкретного артефакта.

## Три слоя версии

| Слой | Пример | Кто читает | Где живёт |
|---|---|---|---|
| SemVer | `8.1.9` | люди: «заметит ли кто-то разницу» | `install\VERSION` (источник), штамп в артефакте, CHANGELOG |
| Счётчик релизов | `(10)` | люди и скрипты: «который по счёту релиз» | `release.state`, штамп, манифест, заголовок CHANGELOG |
| Манифест | `build-info.json` | аудит: «какие файлы с какими хешами вошли» | `install\build-info.json` |

Вместе это выглядит как `8.1.9 (10)` — семантическая версия и номер релиза.

## Где смотреть версию

| Где | Что видно |
|---|---|
| Артефакт (книга — свойства файла; exe — свойства; веб — version.json) | `BuildVersion`, `BuildDate`, `BuildSrcMd5`, `BuildReleaseNo` |
| `install\VERSION` | SemVer (первая строка) и человеческое описание следующего релиза |
| `CHANGELOG.md` | что менялось от версии к версии: описание, затем техника |
| `install\build-info.json` | манифест последнего релиза: файлы и хеши |

`BuildSrcMd5` отвечает на вопрос «артефакт совпадает с исходниками»: хеш
прежний, а исходники правились — правку в артефакт никто не ставил.

## Правило «где живёт версия»

- скрипты-утилиты — версия в шапке файла;
- рабочий артефакт — штамп внутри (Excel: `CustomDocumentProperties`);
- имя файла — только у неизменяемых снимков/архивов;
- нет внутреннего поля — `version.json` рядом с артефактом.

## Файлы механизма (в проекте)

| Файл | Назначение | Правится руками |
|---|---|---|
| `install\VERSION` | SemVer + описание следующего релиза | только описание |
| `install\release.state` | хеши и `release_no` прошлого релиза | **никогда** |
| `install\build-info.json` | манифест релиза | **никогда** (генерируется) |
| `CHANGELOG.md` | журнал версий | **никогда** |
| `install\migrations\*.ps1` | доп. код версии | да, при необходимости |
| `install\install.ps1` | ядро механизма | редко (точки адаптации) |

## Если что-то пошло не так

| Маркер | Что значит |
|---|---|
| `RELEASE_SOURCES_SAME` | исходники не менялись, версия не поднимается — нормально |
| `DESC_EMPTY` | описание не заполнено — запись пойдёт с плейсхолдером |
| `BUILD_FAIL` / `VERIFY_FAIL` | сборка/проверка упала — версия не записана |
| `RELEASE_FAIL` | релиз прерван; версия, журнал, state и манифест не тронуты |
| `RELEASE_OK <версия> (n)` | всё прошло |

## Чего механизм не делает

- не переименовывает артефакт (имя — не носитель версии);
- не пишет версию, если сборка не прошла;
- не трогает данные артефакта вне явно описанных миграций.
