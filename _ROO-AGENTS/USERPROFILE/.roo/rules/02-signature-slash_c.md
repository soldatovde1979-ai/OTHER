При получении команды `/c сигн` (обновление DIRTY-сигнатур) или `/c sig renew` (полная пересборка всех сигнатур).

Путь к сигнатурам: `./src/sig/<ИмяМодуля>.sig.md`.

## Сценарий sign (`/c сигн`) — обновление DIRTY-модулей

0. Если файлов `./src/sig/*.sig.md` нет вообще — создать сигнатуру для каждого модуля, найденного в `./src/` и вложенных папках, по шаблону ниже (статус `CLEAN`, дата — сегодняшняя), вывести отчёт о созданных сигнатурах и завершить.
1. Найти все файлы `./src/sig/*.sig.md` со статусом `DIRTY`.
2. Для каждого DIRTY-модуля прочитать полный текущий код модуля (или только изменённую часть, если известно, что менялось — например, из истории текущей сессии) и переписать сигнатуру по шаблону ниже (все описания должны быть максимально конкретными и понятными без чтения кода).
3. Если модуль помечен `DIRTY`, но при чтении кода изменений по сути не найдено (например, поправили только комментарий) — всё равно пересобрать сигнатуру и снять флаг, не оставлять DIRTY из экономии.
4. Если DIRTY-модулей нет — вывести «Сигнатуры актуальны», ничего не делать.
5. В конце — короткий отчёт: какие модули пересобраны, у каких сигнатура не менялась по содержанию (только флаг снят).

## Сценарий sig renew (`/c sig renew`) — полная пересборка всех сигнатур

1. Найти все модули в `./src/` рекурсивно, исключая файлы сигнатур `*.sig.md`.
2. Для каждого модуля прочитать полный текущий код и переписать сигнатуру по шаблону ниже (статус `CLEAN`, дата — сегодняшняя); если сигнатуры нет — создать.
3. Сигнатуры, у которых модуль в `./src/` отсутствует, оставить без изменений и перечислить в отчёте (удалять только по явному указанию).
4. Итоговый отчёт: сколько сигнатур пересобрано, какие созданы, какие не изменились.

## Шаблон сигнатуры

```markdown
# <ИмяМодуля>

Статус: CLEAN
Обновлено: ДД.ММ.ГГГГ

## Назначение
Одна-две строки - зачем модуль существует.

## Процедуры / Функции

### ИмяПроцедуры(Параметр1, Параметр2 = Знач) : ТипВозврата
- Назначение: зачем процедура/функция существует. (одна-две строки дающие максимальное понимание)
- Вход: что ожидает по смыслу, не только тип + краткое описание параметров
- Выход: что возвращает, кратко, но понятно суть и тип
- Побочные эффекты: запись в регистры, вызов внешних источников, изменение глобальных переменных модуля, обращение к БД. Если их нет — писать "нет побочных эффектов", не пропускать пункт.
```
