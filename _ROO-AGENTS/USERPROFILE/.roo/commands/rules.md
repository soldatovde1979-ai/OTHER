# Консолидация rules.md

## Задача
Собери все файлы `rules.md` (или `RULES.md`, если в проекте другой регистр) из всех проектов/директорий текущего рабочего пространства VSCode, сжми и оптимизируй их формулировки, объединив похожие правила, и извлеки **универсальные** правила.

**Обработка параметров команды:**
- **Без параметров (по умолчанию):** собираются только универсальные правила со всех проектов. Проектно-специфичные правила собираются **исключительно** из корневого `rules.md` (переносятся в отдельный раздел).
- **Параметр `all` или смысловые фразы-триггеры («все правила», «включить специализированные», «со всех подпроектов» и т. д.):** собираются универсальные правила со всех проектов, а также **все проектно-специфичные правила** из всех найденных файлов (включая подпроекты), которые группируются по соответствующим проектам.

Из корневого `rules.md` (тот, что обновляется и уходит в `rules.bak`) проектно-специфичные правила сохраняются в любом режиме. 

Старайся не задавать вопросов, задавай только если выполняемая операция не может быть откатана назад. 

## Порядок действий

1. **Проверь аргументы и контекст команды**
   Определи режим работы:
   - Если передан аргумент `all`, либо в запросе/описании присутствуют фразы «включить все правила», «включить специализированные правила», «собрать всё» или аналогичные по смыслу — активируй режим полной сборки (включая специфичные правила подпроектов).
   - Если аргументы и подобные указания отсутствуют — используй режим по умолчанию.

2. **Найди источники**
   Рекурсивно найди все файлы `rules.md` / `RULES.md` в пределах текущего рабочего пространства VSCode, включая корневой `rules.md` в папке исполнения команды.
   Если файлов не найдено — останови генерацию и выведи: `Для генерации ответа необходимы данные:` с запросом путей к проектам.

3. **Прочитай и сжми каждый файл**
   Прочитай содержимое каждого найденного `rules.md`.
   - **Предварительное сжатие:** Первым шагом сократи текст каждого файла — объедини близкие по смыслу пункты, однотипные ограничения и повторяющиеся проблемы в единые емкие формулировки.
   - Не додумывай правила, которых нет в текстах.

4. **Классифицируй правила**
   Раздели сжатые правила каждого файла на:
   - **Универсальное** — применимо к любому проекту вне зависимости от стека/домена (правила именования, работа с секретами, git-конвенции, стиль коммитов, общие принципы безопасности, обработка ошибок). **К Универсальным также относятся категории:** Терминалы Windows, Документация, Git, Инструменты и поиск.
   - **Проектно-специфичное** — привязано к конкретному стеку, домену, названию проекта, конкретным путям, доменным сущностям, версиям платформы, бизнес-логике.

   Пограничные правила относи к проектно-специфичным.

5. **Обработка в зависимости от режима**
   - **Режим по умолчанию:**
     - Из **всех проектных `rules.md`** (кроме корневого) — берёшь только универсальные правила, проектно-специфичные отбрасываешь.
     - Из **корневого `rules.md`** — берёшь и универсальные (наравне с остальными), и проектно-специфичные (для шага 8).
   - **Режим полной сборки (`all` / смысловые фразы):**
     - Из **всех `rules.md`** (включая подпроекты и корневой) — берёшь универсальные правила, а также сохраняешь **все проектно-специфичные правила**, фиксируя относительный путь/название подпроекта для каждого из них.

6. **Консолидируй и дедуплицируй**
   Среди всех собранных универсальных правил объедини похожие по смыслу пункты из разных файлов в единую емкую структуру. При наличии противоречий выбери наиболее строгий/безопасный вариант.

7. **Сделай бэкап**
   Если в корне workspace уже существует `rules.md` — переименуй его в `rules.bak` перед созданием нового файла.

8. **Сформируй новый rules.md**
   Собери итоговый файл с лаконичными формулировками по структуре:

   **Для режима по умолчанию:**
   ```markdown
   # Общие правила проекта

   ## <Категория 1>
   - Правило 1
   - Правило 2

   ## <Категория 2>
   - Правило 1

   # Проектно-специфичные правила
   - Правило 1 (из корневого rules.md)
